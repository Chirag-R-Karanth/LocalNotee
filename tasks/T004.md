## GOAL
Filesystem layer for projects: create, atomic snapshot, load with journal replay, list, delete. Pure JVM, fully tested on temp dirs.

## FILES

- `Logger.kt`, `FileUtil.kt`, `ProjectStore.kt`
- Test: `app/src/test/java/com/localnote/app/store/ProjectStoreTest.kt`

## SPEC
```kotlin
package com.localnote.app.store
fun interface Logger { fun e(msg: String, t: Throwable?) }

object FileUtil {
    /** Atomic write per API_CHEATSHEET F. */
    fun writeAtomic(target: java.io.File, bytes: ByteArray)
}

data class ProjectMeta(val id: String, val title: String, val pageCount: Int, val updatedAt: Long)
class ProjectCorruptException(message: String, cause: Throwable? = null) : Exception(message, cause)

class ProjectStore(private val root: java.io.File, private val logger: Logger) {
    fun projectDir(id: String): java.io.File          // root/id (does not create)
    fun journalFile(id: String): java.io.File         // projectDir/journal.jsonl
    fun sourcePdfFile(id: String): java.io.File       // projectDir/source.pdf
    fun create(project: Project)                      // mkdirs, writes project.json and meta.json (atomic)
    fun writeSnapshot(project: Project)               // atomic project.json, THEN truncate journal, THEN meta.json
    fun load(id: String): Project                     // snapshot + journal replay (ARCHITECTURE 3 Load)
    fun listMeta(): List<ProjectMeta>                 // newest updatedAt first; skips dirs with unreadable meta.json (logs)
    fun delete(id: String)                            // deletes the whole directory recursively
}
```
`meta.json` fields: `id`, `title`, `pageCount`, `updatedAt`. Journal replay uses `ProjectJson.applyOp` line by line; the final unparseable line is ignored silently; an unparseable non-final line is logged via `logger.e` and skipped. Blank lines are ignored.
